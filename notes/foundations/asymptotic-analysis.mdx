## Why Growth Beats Constants

Suppose you want to check whether a list of $n$ numbers contains any duplicates. Two straightforward approaches:

- **Compare every pair:** check item 0 against every later item, then item 1 against every later item, and so on. That takes roughly $\frac{n^2}{2}$ comparisons.
- **Track what you have seen:** walk through the list once and check membership in a hash set. Even if hashing is 10× slower per step than a plain comparison, it takes roughly $10n$ work.

Compare the two as $n$ grows:

<div class="note-table" role="region" aria-label="Comparing quadratic and linear growth" tabindex="0">

| Input size $n$ | Check every pair ($\approx n^2/2$) | Hash set ($\approx 10n$) | Faster |
|---:|---:|---:|---|
| $10$ | $50$ | $100$ | Pairs |
| $100$ | $5{,}000$ | $1{,}000$ | Hash set (5×) |
| $1{,}000$ | $500{,}000$ | $10{,}000$ | Hash set (50×) |
| $1{,}000{,}000$ | $5 \times 10^{11}$ | $10^{7}$ | Hash set (50,000×) |

</div>

At $n = 10$, the constant factor wins. At $n = 1{,}000{,}000$, the constant factor is irrelevant — the **shape** of the curve ($n^2$ vs. $n$) decides whether the code finishes in milliseconds or minutes.

**Asymptotic analysis** captures that shape. Instead of predicting exact seconds on a specific CPU, it describes how an algorithm's time or memory scales as input size $n$ grows large.

Suppose a problem allows roughly $10^7$ inexpensive operations in total. These are illustrative sizes, not universal cutoffs:

<div class="note-table" role="region" aria-labelledby="estimate-feasibility-from-a-work-budget" tabindex="0">

| Growth | Example input size | Representative work |
|---|---:|---:|
| $n!$ | $10$ | $10! \approx 3.6 \times 10^6$ |
| $2^n$ | $20$ | $2^{20} \approx 10^6$ |
| $n^3$ | $100$ | $10^6$ |
| $n^2$ | $1{,}000$ | $10^6$ |
| $n \log_2 n$ | $100{,}000$ | $\approx 1.7 \times 10^6$ |
| $n$ | $1{,}000{,}000$ | $10^6$ |

</div>

Factorial and exponential growth are not interchangeable: $20! \approx 2.43 \times 10^{18}$, far beyond this budget. Also remember that reading $n$ items already costs $\Omega(n)$; sublinear algorithms ($O(\log n)$, $O(1)$) assume random access or prior preprocessing.

## Counting Rules

Before introducing formal symbols, here is how you turn code into a growth class in practice.

<aside class="note-callout" aria-labelledby="cost-model-label">

<p id="cost-model-label" class="note-callout-label">Cost model for this note</p>

Arithmetic, array indexing, and comparisons of bounded-size values count as $O(1)$. A print statement counts as one body operation, not an I/O benchmark. If values grow into arbitrary-precision integers or long strings, count their arithmetic, comparison, or hashing costs separately.

</aside>

### 1. Drop Constants

$$
O(2n) \to O(n) \qquad O(500) \to O(1) \qquad O\!\left(\frac{n}{2}\right) \to O(n)
$$

A constant multiplier scales the curve vertically without changing its shape. Constants still matter in real systems (especially for small $n$), which is why we keep them in mind when two algorithms share the same asymptotic class.

### 2. Drop Lower-Order Terms

$$
O(n^2 + n) \to O(n^2) \qquad O(n + \log n) \to O(n) \qquad O(n^3 + n^2 + n) \to O(n^3)
$$

At $n = 10^6$, $n^2 = 10^{12}$ while $n = 10^6$ — a million times smaller. Only the fastest-growing term survives.

### 3. Different Variables Stay Separate

$$
O(n + m) \text{ stays } O(n + m) \qquad O(n \cdot m) \text{ stays } O(n \cdot m)
$$

You can only simplify if you know how the variables relate. If $m = O(n)$, then $O(n + m) = O(n)$; if $m$ and $n$ are independent (like vertices $V$ and edges $E$, or two separate arrays), keep both.

### 4. Sequential Steps Add, Then Simplify

```python
for i in range(n):    # O(n)
    print(i)
for j in range(n):    # O(n)
    print(j * j)
# Total: O(n) + O(n) = O(2n) = O(n)
```
```julia
for i in 1:n          # O(n)
    println(i)
end
for j in 1:n          # O(n)
    println(j * j)
end
# Total: O(n) + O(n) = O(2n) = O(n)
```
```ts
for (let i = 0; i < n; i++) {   // O(n)
  console.log(i);
}
for (let j = 0; j < n; j++) {   // O(n)
  console.log(j * j);
}
// Total: O(n) + O(n) = O(2n) = O(n)
```
```rust
for i in 0..n {       // O(n)
    println!("{i}");
}
for j in 0..n {       // O(n)
    println!("{}", j * j);
}
// Total: O(n) + O(n) = O(2n) = O(n)
```

One loop followed by another adds their costs; dropping constants and lower-order terms leaves the dominant stage.

### 5. Nested Loops Multiply (Count the Inner Iterations)

```python
for i in range(n):      # O(n)
    for j in range(n):  # O(n)
        print(i, j)     # O(1)
# Total: O(n²)
```
```julia
for i in 1:n            # O(n)
    for j in 1:n        # O(n)
        println(i, " ", j)  # O(1)
    end
end
# Total: O(n²)
```
```ts
for (let i = 0; i < n; i++) {     // O(n)
  for (let j = 0; j < n; j++) {   // O(n)
    console.log(i, j);            // O(1)
  }
}
// Total: O(n²)
```
```rust
for i in 0..n {         // O(n)
    for j in 0..n {     // O(n)
        println!("{i} {j}");  // O(1)
    }
}
// Total: O(n²)
```

When the inner loop bound depends on `i`, sum its iterations rather than guessing:

```python
for i in range(n):          # O(n)
    for j in range(i):      # runs 0, 1, 2, ..., n-1 times
        print(i, j)
# Total: 0 + 1 + 2 + ... + (n-1) = n(n-1)/2 = O(n²)
```
```julia
for i in 1:n                # O(n)
    for j in 1:i-1          # runs 0, 1, 2, ..., n-1 times
        println(i, " ", j)
    end
end
# Total: 0 + 1 + 2 + ... + (n-1) = n(n-1)/2 = O(n²)
```
```ts
for (let i = 0; i < n; i++) {     // O(n)
  for (let j = 0; j < i; j++) {   // runs 0, 1, 2, ..., n-1 times
    console.log(i, j);
  }
}
// Total: 0 + 1 + 2 + ... + (n-1) = n(n-1)/2 = O(n²)
```
```rust
for i in 0..n {             // O(n)
    for j in 0..i {         // runs 0, 1, 2, ..., n-1 times
        println!("{i} {j}");
    }
}
// Total: 0 + 1 + 2 + ... + (n-1) = n(n-1)/2 = O(n²)
```

Here the triangular inner loop does half the work of a full square, which is still $\Theta(n^2)$ (derived in [Example 2](#example-2--triangular-sum)). By contrast, if the inner loop runs a *constant* number of times (say `100`), the total is $O(n)$; if it halves `i` each step, the total is $O(n \log n)$ (derived in [Example 4](#example-4--halving-inside-a-linear-loop)).

### 6. Conditionals: Respect Which Inputs Reach Each Branch

```python
if len(arr) < 100:
    bubble_sort(arr)    # O(n²) — only runs for n < 100
else:
    merge_sort(arr)     # O(n log n) — runs for all large n
# Worst-case growth: O(n log n)
```
```julia
if length(arr) < 100
    bubble_sort!(arr)   # O(n²) — only runs for n < 100
else
    merge_sort(arr)     # O(n log n) — runs for all large n
end
# Worst-case growth: O(n log n)
```
```ts
if (arr.length < 100) {
  bubbleSort(arr);      // O(n²) — only runs for n < 100
} else {
  mergeSort(arr);       // O(n log n) — runs for all large n
}
// Worst-case growth: O(n log n)
```
```rust
if arr.len() < 100 {
    bubble_sort(&mut arr);  // O(n²) — only runs for n < 100
} else {
    merge_sort(&arr);       // O(n log n) — runs for all large n
}
// Worst-case growth: O(n log n)
```

Do not blindly take the max of both branches. Here `bubble_sort` is capped at $n < 100$ (a fixed constant cost), so as $n \to \infty$ only `merge_sort` runs and the worst-case growth is $\Theta(n \log n)$. If *either* branch could be taken for arbitrarily large $n$, then the slower branch would dominate the worst case.

## Formal Notation

Think of asymptotic notation as **inequality symbols for growth rates**:

<div class="note-table" role="region" aria-label="Intuitive summary of asymptotic notations" tabindex="0">

| Notation | Meaning | Analogy |
|----------|---------|---------|
| $f = O(g)$ | $f$ grows at most as fast as $g$ | $f \leq g$ (up to a constant) |
| $f = \Omega(g)$ | $f$ grows at least as fast as $g$ | $f \geq g$ (up to a constant) |
| $f = \Theta(g)$ | $f$ grows at the same rate as $g$ | $f = g$ (up to constants) |
| $f = o(g)$ | $f$ grows strictly slower than $g$ | $f < g$ (asymptotically) |
| $f = \omega(g)$ | $f$ grows strictly faster than $g$ | $f > g$ (asymptotically) |

</div>

### Choose the Function Before the Bound

A common misconception is that "$O$ means worst case and $\Omega$ means best case." They are separate ideas:

- **Case** (best, average, worst) picks *which* cost function $f(n)$ you are analysing.
- **Notation** ($O$, $\Omega$, $\Theta$) describes a bound on *that* function.

For linear search:
- Best-case time is $\Theta(1)$ (target is at index 0).
- Worst-case time is $\Theta(n)$ (target is at the end or absent) — so $O(n)$ is a tight upper bound, and $O(n^2)$ is also a true (just loose) upper bound.

<section class="notation-definition" aria-labelledby="big-o--upper-bound">

### Big O — Upper Bound

"The algorithm does *at most* this much work."

$$
f(n) = O(g(n)) \iff \exists\; c > 0,\; n_0 \in \mathbb{N} \;:\; f(n) \leq c \cdot g(n) \quad \forall\; n \geq n_0
$$

Beyond some starting size $n_0$, $f$ never exceeds a constant multiple $c$ of $g$. Big O is the default notation in interviews and algorithm analysis.

</section>

<section class="notation-definition" aria-labelledby="big-omega--lower-bound">

### Big Omega — Lower Bound

"The algorithm does *at least* this much work."

$$
f(n) = \Omega(g(n)) \iff \exists\; c > 0,\; n_0 \in \mathbb{N} \;:\; f(n) \geq c \cdot g(n) \quad \forall\; n \geq n_0
$$

Lower bounds describe either a single algorithm or an entire problem class. For comparison sorting, a decision tree must distinguish $n!$ orderings, so its deepest path needs at least $\log_2(n!) = \Omega(n \log n)$ comparisons.

</section>

<section class="notation-definition" aria-labelledby="big-theta--tight-bound">

### Big Theta — Tight Bound

"The algorithm grows at *exactly* this rate, up to constants."

$$
f(n) = \Theta(g(n)) \iff \exists\; c_1, c_2 > 0,\; n_0 \;:\; c_1 \cdot g(n) \leq f(n) \leq c_2 \cdot g(n) \quad \forall\; n \geq n_0
$$

$\Theta$ means $O$ and $\Omega$ simultaneously — the function is sandwiched from above and below. Merge sort is $\Theta(n \log n)$ in every case.

</section>

<aside class="note-callout" aria-labelledby="little-o-label">

<p id="little-o-label" class="note-callout-label">Strict bounds: little-o and little-omega</p>

When you want a **strict** comparison (like $<$ instead of $\leq$), use limits:

$$
f(n) = o(g(n)) \iff \lim_{n \to \infty} \frac{f(n)}{g(n)} = 0 \qquad\qquad f(n) = \omega(g(n)) \iff \lim_{n \to \infty} \frac{f(n)}{g(n)} = \infty
$$

For example, $n = o(n^2)$ because $n / n^2 \to 0$, whereas $n \neq o(n)$ because $n / n = 1$.

</aside>

## Analysing Recursive Algorithms

Loops let you multiply iteration counts directly. Recursion instead expresses an algorithm's cost in terms of itself — a **recurrence relation**.

### Step 1: Write the Recurrence

For any recursive function, identify three things:
1. **Non-recursive work** done at the current call
2. **Number of recursive calls** made
3. **Size of each subproblem**

**Example — binary search:**

```python
def binary_search(arr, target, lo, hi):
    if lo > hi:
        return -1
    mid = (lo + hi) // 2
    if arr[mid] == target:
        return mid
    elif arr[mid] < target:
        return binary_search(arr, target, mid + 1, hi)
    else:
        return binary_search(arr, target, lo, mid - 1)
```
```julia
# Call with lo = 1, hi = length(arr) (Julia is 1-based).
function binary_search(arr, target, lo, hi)
    if lo > hi
        return nothing
    end
    mid = (lo + hi) ÷ 2
    if arr[mid] == target
        return mid
    elseif arr[mid] < target
        return binary_search(arr, target, mid + 1, hi)
    else
        return binary_search(arr, target, lo, mid - 1)
    end
end
```
```ts
function binarySearch(arr: number[], target: number, lo: number, hi: number): number {
  if (lo > hi) {
    return -1;
  }
  const mid = Math.floor((lo + hi) / 2);
  if (arr[mid] === target) {
    return mid;
  } else if (arr[mid] < target) {
    return binarySearch(arr, target, mid + 1, hi);
  } else {
    return binarySearch(arr, target, lo, mid - 1);
  }
}
```
```rust
// Searches arr[lo..hi] with hi exclusive (call with 0, arr.len()), so there
// is no `mid - 1` to underflow. Same recurrence: one call on half the range.
fn binary_search(arr: &[i32], target: i32, lo: usize, hi: usize) -> Option<usize> {
    if lo >= hi {
        return None;
    }
    let mid = lo + (hi - lo) / 2;
    if arr[mid] == target {
        Some(mid)
    } else if arr[mid] < target {
        binary_search(arr, target, mid + 1, hi)
    } else {
        binary_search(arr, target, lo, mid)
    }
}
```

One recursive call on half the range, plus constant work:

$$
T(n) = T\!\left(\frac{n}{2}\right) + c
$$

Unrolling (repeated substitution) makes the total obvious:

$$
T(n) = T\!\left(\tfrac{n}{2}\right) + c = T\!\left(\tfrac{n}{4}\right) + 2c = \cdots = T\!\left(\tfrac{n}{2^k}\right) + kc
$$

It hits the base case when $n / 2^k = 1$, i.e. $k = \log_2 n$, giving $T(n) = T(1) + c\log_2 n = \Theta(\log n)$.

### Step 2: Picture the Recursion Tree First

Now consider **merge sort** — two recursive calls on size $n/2$, plus a linear merge:

```python
def merge_sort(arr):
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    left = merge_sort(arr[:mid])    # T(n/2)
    right = merge_sort(arr[mid:])   # T(n/2)
    return merge(left, right)       # O(n)
```
```julia
# merge_sorted, not merge: Base.merge already exists (for dictionaries)
function merge_sort(arr)
    if length(arr) <= 1
        return arr
    end
    mid = length(arr) ÷ 2
    left = merge_sort(arr[1:mid])       # T(n/2)
    right = merge_sort(arr[mid+1:end])  # T(n/2)
    return merge_sorted(left, right)    # O(n)
end
```
```ts
function mergeSort(arr: number[]): number[] {
  if (arr.length <= 1) {
    return arr;
  }
  const mid = Math.floor(arr.length / 2);
  const left = mergeSort(arr.slice(0, mid));  // T(n/2)
  const right = mergeSort(arr.slice(mid));    // T(n/2)
  return merge(left, right);                  // O(n)
}
```
```rust
fn merge_sort(arr: &[i32]) -> Vec<i32> {
    if arr.len() <= 1 {
        return arr.to_vec();
    }
    let mid = arr.len() / 2;
    let left = merge_sort(&arr[..mid]);   // T(n/2)
    let right = merge_sort(&arr[mid..]);  // T(n/2)
    merge(&left, &right)                  // O(n)
}
```

Recurrence: $T(n) = 2T(n/2) + n$. Draw the work done at each level of the call tree:

```text
Level 0:            n                     → total = n
                 /     \
Level 1:       n/2     n/2                → total = n
              /   \   /   \
Level 2:    n/4 n/4 n/4 n/4               → total = n
             ⋮               ⋮
Level log₂n: 1   1  ...  1   (n leaves)   → total = n
```

Every level does $n$ work, and there are $\log_2 n + 1$ levels — so total work is $n(\log_2 n + 1) = \Theta(n \log n)$.

In general, any divide-and-conquer tree has a **tug-of-war** between the branching factor (which creates more nodes as you go down) and the shrinking subproblem size (which makes each node cheaper). Only three things can happen as you move down the tree:

1. **Work explodes toward the leaves** (branching wins) $\implies$ the **leaves** dominate total work.
2. **Work stays equal at every level** (tie, like merge sort) $\implies$ total work is **(work per level) $\times$ (number of levels)**, picking up a $\log n$ factor.
3. **Work shrinks toward the leaves** (root wins, like $n + n/2 + n/4 + \cdots \leq 2n$) $\implies$ the **root** dominates total work.

### Step 3: The Master Theorem (Shortcut for Those Three Shapes)

The Master Theorem turns that three-way tug-of-war into a formula for recurrences of the form:

$$
T(n) = aT\!\left(\frac{n}{b}\right) + f(n)
$$

where $a \geq 1$ is the number of subproblems, $b > 1$ is the shrink factor, and $f(n)$ is the non-recursive work at the root (with $T(1) = \Theta(1)$).

The tree has $\log_b n$ levels and $a^{\log_b n} = n^{\log_b a}$ leaves. Define the **critical exponent** $c^* = \log_b a$, so **$n^{c^*}$ is the leaf work** and **$f(n)$ is the root work**:

<div class="note-table" role="region" aria-labelledby="step-3-the-master-theorem-shortcut-for-those-three-shapes" tabindex="0">

| Case | Who wins the tug-of-war? | Condition | Solution |
|------|--------------------------|-----------|----------|
| **Case 1** | Leaves dominate | $f(n) = O(n^{c^* - \varepsilon})$ for some $\varepsilon > 0$ | $T(n) = \Theta(n^{c^*})$ |
| **Case 2** | Tie across levels | $f(n) = \Theta(n^{c^*} \log^k n)$ for $k \geq 0$ | $T(n) = \Theta(n^{c^*} \log^{k+1} n)$ |
| **Case 3** | Root dominates | $f(n) = \Omega(n^{c^* + \varepsilon})$ for some $\varepsilon > 0$, **and** $a f(n/b) \leq \rho f(n)$ for some $\rho < 1$ | $T(n) = \Theta(f(n))$ |

</div>

**Applying it to five common recurrences:**

<div class="note-table" role="region" aria-label="Master Theorem recurrence examples" tabindex="0">

| Recurrence | $c^* = \log_b a$ | Compare $f(n)$ vs $n^{c^*}$ | Case | Result |
|---|---|---|---|---|
| $T(n) = 2T(n/2) + n$ | $\log_2 2 = 1$ | $n$ vs $n$ (tie) | 2 ($k=0$) | $\Theta(n \log n)$ |
| $T(n) = 4T(n/2) + n$ | $\log_2 4 = 2$ | $n$ vs $n^2$ (leaves win) | 1 ($\varepsilon=1$) | $\Theta(n^2)$ |
| $T(n) = T(n/2) + n$ | $\log_2 1 = 0$ | $n$ vs $1$ (root wins; $\frac{n}{2} \le \frac{1}{2}n$) | 3 ($\varepsilon=1$) | $\Theta(n)$ |
| $T(n) = 9T(n/3) + n^2$ | $\log_3 9 = 2$ | $n^2$ vs $n^2$ (tie) | 2 ($k=0$) | $\Theta(n^2 \log n)$ |
| $T(n) = 2T(n/2) + n^2$ | $\log_2 2 = 1$ | $n^2$ vs $n$ (root wins; $2(\frac{n}{2})^2 = \frac{1}{2}n^2$) | 3 ($\varepsilon=1$) | $\Theta(n^2)$ |

</div>

> The Master Theorem only applies to equal-size splits $T(n) = aT(n/b) + f(n)$. It does **not** apply to unequal splits like $T(n) = T(n/3) + T(2n/3) + n$ or subtractive recurrences like $T(n) = T(n-1) + O(1)$ — draw the recursion tree or unroll instead.

## Amortized Analysis

Sometimes an operation is almost always cheap, with an occasional expensive spike. A dynamic array (Python `list`, Rust `Vec`, JS `Array`) appends in $O(1)$ normally, but when it runs out of capacity it allocates a larger buffer and copies all $n$ elements — an $O(n)$ spike.

If you only looked at the single worst call, you might think $n$ appends cost $O(n^2)$. **Amortized analysis** bounds the *total* cost of any sequence of $n$ operations and divides by $n$. Unlike average-case analysis, it makes **no randomness assumption** — the guarantee holds for *every* sequence.

### Trace It First: Doubling a Dynamic Array

Start with capacity $1$ and double whenever the array is full. Watch the first 9 appends:

<div class="note-table" role="region" aria-label="Dynamic array doubling trace" tabindex="0">

| Append # | Capacity before → after | Resize copies | New write | Cost of this append | Cumulative cost | Running avg / append |
|---:|---|---:|---:|---:|---:|---:|
| 1 | $1 \to 1$ | 0 | 1 | 1 | 1 | 1.00 |
| 2 | $1 \to 2$ | 1 | 1 | 2 | 3 | 1.50 |
| 3 | $2 \to 4$ | 2 | 1 | 3 | 6 | 2.00 |
| 4 | $4 \to 4$ | 0 | 1 | 1 | 7 | 1.75 |
| 5 | $4 \to 8$ | 4 | 1 | 5 | 12 | 2.40 |
| 6 | $8 \to 8$ | 0 | 1 | 1 | 13 | 2.17 |
| 7 | $8 \to 8$ | 0 | 1 | 1 | 14 | 2.00 |
| 8 | $8 \to 8$ | 0 | 1 | 1 | 15 | 1.88 |
| 9 | $8 \to 16$ | 8 | 1 | 9 | 24 | 2.67 |

</div>

Notice the pattern: every time a resize gets twice as expensive, you also get twice as many cheap $O(1)$ appends before the next resize. Across $n$ appends, the resize copies form a geometric sum $1 + 2 + 4 + \cdots < 2n$. Adding the $n$ new-element writes gives fewer than $3n$ total writes — **amortized $\Theta(1)$ per append**.

*(CPython lists use a smaller over-allocation factor than 2×, which still grows geometrically and preserves amortized $O(1)$ append.)*

### Three Ways to Prove Amortized Bounds

- **Aggregate method:** Sum the total cost of $n$ operations directly and divide by $n$ (what we just did above).
- **Accounting (banker's) method:** Overcharge cheap operations and save the surplus as "credit" on elements to pay for future expensive operations. Example: a stack with `multipop(k)` charges 2 credits per `push` (1 to push, 1 stored on the item to pay for its eventual pop). Since every item can be popped at most once, $n$ total operations cost at most $2n = O(n)$, or amortized $O(1)$ each.
- **Potential method:** Define a potential function $\Phi(\text{state}) \geq 0$ representing stored "energy" in the structure; amortized cost is $\text{actual cost} + \Delta\Phi$. Most general (used for splay trees and Fibonacci heaps), rarely required in standard interviews.

```ts
function example(arr: number[]): void {
```


<div class="example-result">

**Time:** $\Theta(n)$. **Extra space:** $O(1)$. The fixed inner loop changes the constant, not the growth rate.

</div>

<div class="example-derivation">

#### Derivation

Let $n = \texttt{len(arr)}$. The outer loop runs $n$ times, and the inner loop always runs 100 times:

$$
\sum_{i=0}^{n-1} 100 = 100n
$$

Since $1 \cdot n \leq 100n \leq 100 \cdot n$ for all $n \geq 1$, the bound is tight: $\Theta(n)$.

### Example 2 — Triangular sum

**Input:** an array of $n$ values. The inner loop runs $i$ times on outer iteration $i$.

```python
def example(arr):
    for i in range(len(arr)):
        for j in range(i):          # runs 0, 1, 2, ..., n-1 times
            print(arr[j])
```
```julia
function example(arr)
    for i in 1:length(arr)

    end
end
```
```ts
function example(arr: number[]): void {
  for (let i = 0; i < arr.length; i++) {

```
```rust
fn example(arr: &[i32]) {

```

<div class="example-result">

**Time:** $\Theta(n^2)$. **Extra space:** $O(1)$. The inner body runs $n(n-1)/2$ times.

</div>

<div class="example-derivation">

#### Derivation

Let $S = 0 + 1 + \cdots + (n-1)$. Write the sum backwards and add term by term:

$$
\begin{aligned}
S  &= 0 + 1 + \cdots + (n-1) \\
S  &= (n-1) + (n-2) + \cdots + 0 \\
2S &= \underbrace{(n-1) + (n-1) + \cdots + (n-1)}_{n \text{ terms}} = n(n-1)
\end{aligned}
$$

So $S = \frac{n(n-1)}{2} = \frac{1}{2}n^2 - \frac{1}{2}n$. For $n \geq 2$, $\frac{1}{4}n^2 \leq S \leq \frac{1}{2}n^2$, giving $\Theta(n^2)$ — half the work of a full $n \times n$ loop, same growth rate.

</div>

</section>

### Example 3 — Logarithmic while loop

**Input:** a positive integer $n$. Each pass halves the remaining value; $n = 0$ skips the loop.

```python
def example(n):
    i = n
    while i > 0:
        i = i // 2
```
```julia
function example(n)
    i = n
    while i > 0
        i = i ÷ 2
    end
end
```
```ts
function example(n: number): void {
  let i = n;
  while (i > 0) {
    i = Math.floor(i / 2);
  }
}
```
```rust
fn example(n: u64) {
    let mut i = n;
    while i > 0 {
        i /= 2;
    }
}
```

<div class="example-result">

**Time:** $\Theta(\log n)$. **Extra space:** $O(1)$. The loop runs $\lfloor \log_2 n \rfloor + 1$ times — doubling $n$ adds just one iteration.

</div>

<div class="example-derivation">

#### Derivation

<section class="calculation-step">

##### 1. Trace a concrete input

For $n = 16$, integer division reaches 1 after four halvings, then needs one final pass to reach 0:

| Iterations ($k$) | Calculation | Value of $i$ |
|---|---|---|
| 0 | $16 / 2^0$ | 16 |
| 1 | $16 / 2^1$ | 8 |
| 2 | $16 / 2^2$ | 4 |
| 3 | $16 / 2^3$ | 2 |
| 4 | $16 / 2^4$ | 1 |
| 5 | $\lfloor 16 / 2^5 \rfloor$ | 0 (stop) |

</section>

<section class="calculation-step">

##### 2. Count the passes

After $k$ passes, $i = \lfloor n/2^k \rfloor$. The loop stops when $\lfloor n/2^k \rfloor = 0 \iff n/2^k < 1 \iff k > \log_2 n$. The smallest such integer is $\lfloor \log_2 n \rfloor + 1$, so $T(n) = \Theta(\log n)$.

</section>

</div>

<aside class="example-takeaway" aria-label="Halving intuition">

#### Why halving stays fast

Doubling $n$ adds only one iteration because the first halving brings $2n$ back to $n$. In binary, `i // 2` drops the last bit ($10100_2 \to 1010_2 \to 101_2$), so the loop runs once per binary digit of $n$: $\approx 10$ times for $1{,}000$, $20$ times for $10^6$, and $30$ times for $10^9$.

</aside>

</section>

<section class="worked-example" aria-labelledby="example-4--halving-inside-a-linear-loop">

### Example 4 — Halving inside a linear loop

**Input:** a positive integer $n$. Two nested loops, where the inner loop halves its counter.

```python
for i in range(n):          # O(n)
    j = i
    while j > 0:
        j = j // 2          # halving: O(log i)
```
```julia
for i in 1:n                # O(n)
    j = i
    while j > 0
        j = j ÷ 2           # halving: O(log i)
    end
end
```
```ts
for (let i = 0; i < n; i++) {     // O(n)
  let j = i;
  while (j > 0) {
    j = Math.floor(j / 2);        // halving: O(log i)
  }
}
```
```rust
for i in 0..n {             // O(n)
    let mut j = i;
    while j > 0 {
        j /= 2;             // halving: O(log i)
    }
}
```

<div class="example-result">

**Time:** $\Theta(n \log n)$. **Extra space:** $O(1)$. Nested loops are not automatically $O(n^2)$.

</div>

<div class="example-derivation">

#### Derivation

From Example 3, for each $i \geq 1$ the inner loop runs $\lfloor \log_2 i \rfloor + 1$ times. Summing over $i$:

$$
\sum_{i=1}^{n-1} \left(\lfloor \log_2 i \rfloor + 1\right) \leq \sum_{i=1}^{n-1} \log_2 i + n = \log_2\big((n-1)!\big) + n \leq n \log_2 n + n = O(n \log n)
$$

For the lower bound, look only at the top half $i \geq n/2$: each of those $\approx n/2$ iterations runs at least $\log_2(n/2)$ times, giving $\Omega(n \log n)$. Therefore the bound is tight: $\Theta(n \log n)$.

</div>

</section>

**Input:** an array of $n$ values, assuming $\Theta(n \log n)$ worst-case sort cost.

```python

```

```julia
    end
end
```
```ts

  for (const x of arr) {          // O(n)
    console.log(x);
  }
  arr.sort((a, b) => a - b);      // O(n log n)

  }
}
```
```rust

```

<div class="example-result">

**Time (worst case):** $\Theta(n \log n)$. The two linear scans are lower-order terms absorbed by the sort.

</div>

<div class="example-derivation">

#### Derivation

The three sequential steps add: $T(n) = c_1 n + c_2 n\log_2 n + c_3 n$. For $n \geq 2$, $\log_2 n \geq 1$, so $n \leq n\log_2 n$ and $T(n) \leq (c_1 + c_2 + c_3)\, n \log_2 n = O(n \log n)$. Since $\frac{n}{n\log n} = \frac{1}{\log n} \to 0$, the linear scans are $o(n \log n)$ and become negligible as $n$ grows.

</div>

</section>

### Example 6 — Binary search + linear duplicate scan

**Input:** a sorted array of $n$ values and a target. Finds the leftmost occurrence by binary searching, then scanning left through duplicates.

```python
def example(arr, target):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target:
            left = mid
            while left > 0 and arr[left - 1] == target:
                left -= 1
            return left
        elif arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```
```julia
function example(arr, target)
    lo, hi = 1, length(arr)
    while lo <= hi
        mid = (lo + hi) ÷ 2
        if arr[mid] == target
            left = mid
            while left > 1 && arr[left - 1] == target
                left -= 1
            end
            return left
        elseif arr[mid] < target
            lo = mid + 1
        else
            hi = mid - 1
        end
    end
    return nothing
end
```
```ts
function example(arr: number[], target: number): number {
  let lo = 0;
  let hi = arr.length - 1;
  while (lo <= hi) {
    const mid = Math.floor((lo + hi) / 2);
    if (arr[mid] === target) {
      let left = mid;
      while (left > 0 && arr[left - 1] === target) {
        left -= 1;
      }
      return left;
    } else if (arr[mid] < target) {
      lo = mid + 1;
    } else {
      hi = mid - 1;
    }
  }
  return -1;
}
```
```rust
fn example(arr: &[i32], target: i32) -> Option<usize> {
    let (mut lo, mut hi) = (0, arr.len());
    while lo < hi {
        let mid = lo + (hi - lo) / 2;
        if arr[mid] == target {
            let mut left = mid;
            while left > 0 && arr[left - 1] == target {
                left -= 1;
            }
            return Some(left);
        } else if arr[mid] < target {
            lo = mid + 1;
        } else {
            hi = mid;
        }
    }
    None
}
```

<div class="example-result">

**Time (worst case):** $\Theta(n)$. **Extra space:** $O(1)$. If every element equals `target`, the linear scan walks $n/2$ steps and wipes out the $O(\log n)$ binary search.

</div>

<div class="example-derivation">

#### Derivation

- **Search phase:** $O(\log n)$ iterations.
- **Scan phase:** runs at most once (returns immediately after), taking at most `mid` $\leq n - 1$ steps.
- **Worst case:** when all elements equal `target`, the first probe hits `mid` $\approx n/2$ and scans all the way to index 0 $\implies \Theta(n)$.
- **Fix:** replace the linear scan with a left-biased binary search to keep worst-case time at $O(\log n)$.

</div>

</section>

<section class="worked-example" aria-labelledby="example-7--branching-recursion-vs-memoisation">

### Example 7 — Branching recursion vs. memoisation

**Input:** a nonnegative integer $n$ (treating integer arithmetic as $O(1)$).

```python
# Naive: recomputes the same subproblems exponentially many times
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)

# Memoised: computes each subproblem 0..n at most once
from functools import lru_cache

@lru_cache(maxsize=None)
def fib_memo(n):
    if n <= 1:
        return n
    return fib_memo(n - 1) + fib_memo(n - 2)
```
```julia
function fib(n)
    n <= 1 && return n
    return fib(n - 1) + fib(n - 2)
end

function fib_memo(n, memo = Dict{Int, Int}())
    n <= 1 && return n
    haskey(memo, n) && return memo[n]
    memo[n] = fib_memo(n - 1, memo) + fib_memo(n - 2, memo)
    return memo[n]
end
```
```ts
function fib(n: number): number {
  if (n <= 1) return n;
  return fib(n - 1) + fib(n - 2);
}

function fibMemo(n: number, memo = new Map<number, number>()): number {
  if (n <= 1) return n;
  const cached = memo.get(n);
  if (cached !== undefined) return cached;
  const result = fibMemo(n - 1, memo) + fibMemo(n - 2, memo);
  memo.set(n, result);
  return result;
}
```
```rust
use std::collections::HashMap;

fn fib(n: u64) -> u64 {
    if n <= 1 { return n; }
    fib(n - 1) + fib(n - 2)
}

fn fib_memo(n: u64, memo: &mut HashMap<u64, u64>) -> u64 {
    if n <= 1 { return n; }
    if let Some(&cached) = memo.get(&n) { return cached; }
    let result = fib_memo(n - 1, memo) + fib_memo(n - 2, memo);
    memo.insert(n, result);
    result
}
```

<div class="example-result">

- **Time (naive):** $\Theta(\phi^n)$ ($\phi \approx 1.618$, often loosely bounded as $O(2^n)$); **Extra space:** $\Theta(n)$ call stack.
- **Time (memoised):** $\Theta(n)$; **Extra space:** $\Theta(n)$ (cache + call stack).

</div>

<div class="example-derivation">

#### Derivation

- **Naive calls:** $C(n) = C(n-1) + C(n-2) + 1$. Upper bound: $C(n) \leq 2C(n-1) + 1 \implies O(2^n)$. Lower bound: $C(n) \geq 2C(n-2) \implies \Omega(\sqrt{2}^{\,n})$. Solving the characteristic equation $x^2 = x + 1$ gives the exact growth rate $\Theta(\phi^n)$ where $\phi = (1 + \sqrt{5})/2 \approx 1.618$.
- **Memoised calls:** only $n + 1$ distinct arguments ($0 \dots n$) exist. Each is computed once and triggers at most 2 lookups, giving $\leq 1 + 2(n+1) = \Theta(n)$ total work.
- **Stack space (both):** only one root-to-leaf path is live on the call stack at once (depth $n$). See [Space Complexity](../space-complexity/#the-call-stack-in-depth) for a step-by-step stack trace.

</div>

</section>

### Example 8 — Two-variable grid recursion

**Input:** positive integers $n$ and $m$ (independent size parameters).

```python
def paths(n, m):
    if n == 0 or m == 0:
        return 1
    return paths(n - 1, m) + paths(n, m - 1)
```
```julia
function paths(n, m)
    (n == 0 || m == 0) && return 1
    return paths(n - 1, m) + paths(n, m - 1)
end
```
```ts
function paths(n: number, m: number): number {
  if (n === 0 || m === 0) {
    return 1;
  }
  return paths(n - 1, m) + paths(n, m - 1);
}
```
```rust
fn paths(n: u64, m: u64) -> u64 {
    if n == 0 || m == 0 {
        return 1;
    }
    paths(n - 1, m) + paths(n, m - 1)
}
```

<div class="example-result">

**Time without memoisation:** $\Theta\!\left(\binom{n+m}{n}\right)$ (exponential when $n = m$). **Time and space with memoisation:** $\Theta(n \cdot m)$.

</div>

<div class="example-derivation">

#### Derivation

- **Without memoisation:** the recurrence is Pascal's identity, so `paths(n, m)` returns $\binom{n+m}{n}$. Every leaf returns 1, so the call tree has $L = \binom{n+m}{n}$ leaves and $2L - 1$ total calls. On a square grid ($n = m$), Stirling's approximation gives $\binom{2n}{n} \sim 4^n / \sqrt{\pi n}$ — exponential.
- **With memoisation:** there are $(n+1)(m+1)$ distinct pairs $(i, j)$, each doing $O(1)$ work $\implies \Theta(nm)$ time and $\Theta(nm)$ space (cache dominates the $O(n+m)$ call stack).

</div>

</section>

## Common Mistakes

1. **Treating $O(1)$ as "fast"** — $O(1)$ means *independent of $n$*, not *small*. A fixed loop of ten million iterations is still $O(1)$ in $n$.
2. **Missing hidden library work** — operations like `x in list`, `arr[a:b]` slicing, or repeated string concatenation look like one line of code but cost $O(n)$ each. Check your language's [Big-O cheatsheets](../python-big-o-cheatsheet/) (`python`, `typescript`, `rust`).
3. **Confusing Big O with worst case** — $O$ is an upper bound on whichever case function you chose (best, average, or worst).
4. **Forgetting call-stack space** — recursive depth $d$ always uses $O(d)$ stack memory even when you allocate no arrays. See [Space Complexity](../space-complexity/).
5. **Assuming hash tables are always $O(1)$** — average case is $O(1)$, worst case (all keys collide) is $O(n)$.
6. **Dropping independent variables** — $O(n + m)$ does not simplify to $O(n)$ unless you know $m = O(n)$.
7. **Over-applying the Master Theorem** — it only covers equal splits $T(n) = aT(n/b) + f(n)$, not $T(n) = T(n-1) + O(1)$ or unequal splits like $T(n/3) + T(2n/3) + n$.

You concatenate $n$ one-character parts, and every concatenation copies the entire existing prefix. Why is this quadratic? What changes with a single join?

<details class="review-answer">
<summary>Show answer</summary>

Copied lengths are $1 + 2 + \cdots + n = n(n+1)/2 = \Theta(n^2)$. A single join allocates once and copies each character once: $\Theta(n)$.

</details>

</section>

<section class="review-question" aria-labelledby="q6--work-versus-live-memory">

### Q6 — Work versus live memory

Why does naive recursive Fibonacci have exponential time but only linear stack space?

<details class="review-answer">
<summary>Show answer</summary>

Time counts every node visited in the recursion tree ($\Theta(\phi^n)$). Space counts the deepest simultaneously live root-to-leaf path, which is $\Theta(n)$ frames.

</details>

</section>

<section class="review-question" aria-labelledby="q7--small-quadratic-subproblems">

### Q7 — Small quadratic subproblems

Why can insertion sort be useful inside a faster hybrid sorting algorithm?

<details class="review-answer">
<summary>Show answer</summary>

On small subarrays (e.g. $< 64$ items), $n^2$ is tiny while insertion sort's low overhead and cache locality beat recursive merge/quicksort. A fixed cutoff does not change the overall $O(n \log n)$ asymptotic bound.

</details>

</section>

<section class="review-question" aria-labelledby="q8--amortized-cost">

### Q8 — Amortized cost

In the doubling-capacity dynamic-array model, why do $n$ appends take linear total work despite occasional $O(n)$ resizes?

<details class="review-answer">
<summary>Show answer</summary>

The resize copies form a geometric series $1 + 2 + 4 + \cdots < 2n$. Plus $n$ ordinary writes, total work is $< 3n = \Theta(n)$, or amortized $\Theta(1)$ per append.

</details>

</section>

<section class="review-question" aria-labelledby="q9--a-shrinking-inner-loop">

### Q9 — A shrinking inner loop

A loop performs $n$ body operations on the first pass, $n-1$ on the next, and so on down to $1$. What is the total?

<details class="review-answer">
<summary>Show answer</summary>

$\sum_{i=1}^{n} i = n(n+1)/2 = \Theta(n^2)$. The average pass still does $\approx n/2$ work across $n$ passes.

</details>

</section>

<section class="review-question" aria-labelledby="q10--construct-an-example">

### Q10 — Construct an example

Give a concrete algorithm with $\Theta(n)$ time and $O(\log n)$ extra space.

<details class="review-answer">
<summary>Show answer</summary>

Recursive DFS over an already-built **balanced binary tree** of $n$ nodes, doing $O(1)$ work per visit without collecting nodes into a list. Every node is visited once ($\Theta(n)$ time) and max call-stack depth is the height $O(\log n)$.

</details>

</section>

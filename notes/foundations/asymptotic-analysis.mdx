## What is Asymptotic Analysis?

Asymptotic analysis describes how an algorithm's resource usage (time or space) scales as the input size $n$ grows toward infinity. The key insight is that we care about the **shape** of the growth curve, not the exact number of operations on any particular machine.

The result is a statement about growth, not a prediction of seconds on a particular machine. Constant factors still matter in practice; asymptotic notation deliberately abstracts them away.

### Choose the function before the bound

Best-case, average-case, and worst-case costs are different functions. You can use $O$, $\Omega$, or $\Theta$ to describe **any** of them. For linear search, best-case time is $\Theta(1)$ and worst-case time is $\Theta(n)$; $O$ does not itself mean “worst case.”

<aside class="note-callout" aria-labelledby="cost-model-label">

<p id="cost-model-label" class="note-callout-label">Cost model for this note</p>

Arithmetic, array access, and comparisons of bounded-size values count as $O(1)$. A print statement counts as one body operation, not a benchmark of I/O. Memory bounds count extra allocations and call-stack frames, including allocated results unless stated otherwise. If values grow into arbitrary-precision integers or long strings, include their arithmetic, comparison, or hashing costs separately.

</aside>

## The Formal Notations

<section class="notation-definition" aria-labelledby="big-o--upper-bound">

### Big O — Upper Bound

"The algorithm does *at most* this much work."

$$
f(n) = O(g(n)) \iff \exists\; c > 0,\; n_0 \in \mathbb{N} \;:\; f(n) \leq c \cdot g(n) \quad \forall\; n \geq n_0
$$

In plain terms: beyond some threshold $n_0$, $f$ never exceeds $g$ by more than a constant factor $c$. Big O is the notation you'll use in almost every interview and analysis.

**Example:** Linear search is $O(n)$ because in the worst case you inspect every element.

</section>

<section class="notation-definition" aria-labelledby="big-omega--lower-bound">

### Big Omega — Lower Bound

"The algorithm does *at least* this much work."

$$
f(n) = \Omega(g(n)) \iff \exists\; c > 0,\; n_0 \in \mathbb{N} \;:\; f(n) \geq c \cdot g(n) \quad \forall\; n \geq n_0
$$

A lower bound can describe one algorithm's cost or establish a limit for an entire problem. For comparison sorting, a decision tree must distinguish $n!$ possible orderings, so its deepest path needs at least $\log_2(n!) = \Omega(n \log n)$ comparisons. This is a worst-case problem lower bound, not a claim that every input needs that many comparisons.

</section>

<section class="notation-definition" aria-labelledby="big-theta--tight-bound">

### Big Theta — Tight Bound

"The algorithm is *exactly* this order of growth, up to constants."

$$
f(n) = \Theta(g(n)) \iff \exists\; c_1, c_2 > 0,\; n_0 \;:\; c_1 \cdot g(n) \leq f(n) \leq c_2 \cdot g(n) \quad \forall\; n \geq n_0
$$

$\Theta$ means $O$ and $\Omega$ simultaneously — the function is sandwiched. Merge sort is $\Theta(n \log n)$: it is always exactly that, best and worst case alike.

</section>

### Little-o and Little-omega

Less common but useful for precise comparisons:

$$
f(n) = o(g(n)) \iff \lim_{n \to \infty} \frac{f(n)}{g(n)} = 0
$$

$$
f(n) = \omega(g(n)) \iff \lim_{n \to \infty} \frac{f(n)}{g(n)} = \infty
$$

Big O says $f$ grows *at most as fast* as $g$. Little-o says $f$ grows *strictly slower* than $g$ — the ratio goes to zero. For example, $n = o(n^2)$ but $n \neq o(n)$.

### Intuitive Summary

<div class="note-table" role="region" aria-labelledby="intuitive-summary" tabindex="0">

| Notation | Meaning | Analogy |
|----------|---------|---------|
| $f = O(g)$ | $f$ grows at most as fast as $g$ | $f \leq g$ (up to constant) |
| $f = \Omega(g)$ | $f$ grows at least as fast as $g$ | $f \geq g$ (up to constant) |
| $f = \Theta(g)$ | $f$ grows at the same rate as $g$ | $f = g$ (up to constants) |
| $f = o(g)$ | $f$ grows strictly slower than $g$ | $f < g$ (asymptotically) |
| $f = \omega(g)$ | $f$ grows strictly faster than $g$ | $f > g$ (asymptotically) |

</div>

## Rules for Calculating Big O

### 1. Drop Constants

$$
O(2n) \to O(n) \qquad O(500) \to O(1) \qquad O\!\left(\frac{n}{2}\right) \to O(n)
$$

A constant factor shifts the curve vertically but doesn't change its shape.

### 2. Drop Lower-Order Terms

$$
O(n^2 + n) \to O(n^2) \qquad O(n + \log n) \to O(n) \qquad O(n^3 + n^2 + n) \to O(n^3)
$$

At large $n$, the dominant term overwhelms everything else. At $n = 10^6$, the $n^2$ term is $10^{12}$ while the $n$ term is only $10^6$ — a factor of a million smaller.

### 3. Different Variables Stay Separate

$$
O(n + m) \text{ stays } O(n + m) \qquad O(n \cdot m) \text{ stays } O(n \cdot m)
$$

You can only simplify if you know the relationship between the variables. If $m = O(n)$ then $O(n + m) = O(n)$, but if $m$ is independent you must keep both.

### 4. Nested Loops Multiply

```python
for i in range(n):      # O(n)
    for j in range(n):  # O(n)
        print(i, j)     # O(1)
# Total: O(n²)
```
```julia
for i in 1:n            # O(n)
    for j in 1:n        # O(n)
        println(i, " ", j)  # O(1)
    end
end
# Total: O(n²)
```
```ts
for (let i = 0; i < n; i++) {     // O(n)
  for (let j = 0; j < n; j++) {   // O(n)
    console.log(i, j);            // O(1)
  }
}
// Total: O(n²)
```
```rust
for i in 0..n {         // O(n)
    for j in 0..n {     // O(n)
        println!("{i} {j}");  // O(1)
    }
}
// Total: O(n²)
```

Each iteration of the outer loop triggers a full pass of the inner loop. Be careful though — not all nested loops are $O(n^2)$:

```python
for i in range(n):          # O(n)
    for j in range(i):      # O(i), not O(n)
        print(i, j)
# Total: 0 + 1 + 2 + ... + (n-1) = n(n-1)/2 = O(n²)
```
```julia
for i in 1:n                # O(n)
    for j in 1:i-1          # O(i), not O(n)
        println(i, " ", j)
    end
end
# Total: 0 + 1 + 2 + ... + (n-1) = n(n-1)/2 = O(n²)
```
```ts
for (let i = 0; i < n; i++) {     // O(n)
  for (let j = 0; j < i; j++) {   // O(i), not O(n)
    console.log(i, j);
  }
}
// Total: 0 + 1 + 2 + ... + (n-1) = n(n-1)/2 = O(n²)
```
```rust
for i in 0..n {             // O(n)
    for j in 0..i {         // O(i), not O(n)
        println!("{i} {j}");
    }
}
// Total: 0 + 1 + 2 + ... + (n-1) = n(n-1)/2 = O(n²)
```

#### Derivation

The body executes $\sum_{i=0}^{n-1} i = n(n-1)/2$ times, giving $\Theta(n^2)$ growth. [Worked Example 2](#example-2--triangular-sum) derives the triangular sum; an inner loop that shrinks with $i$ changes the count, but not the quadratic order.

```python
for i in range(n):          # O(n)
    j = i
    while j > 0:
        j = j // 2          # halving: O(log i)
# Total: O(n log n)
```
```julia
for i in 1:n                # O(n)
    j = i
    while j > 0
        j = j ÷ 2           # halving: O(log i)
    end
end
# Total: O(n log n)
```
```ts
for (let i = 0; i < n; i++) {     // O(n)
  let j = i;
  while (j > 0) {
    j = Math.floor(j / 2);        // halving: O(log i)
  }
}
// Total: O(n log n)
```
```rust
for i in 0..n {             // O(n)
    let mut j = i;
    while j > 0 {
        j /= 2;             // halving: O(log i)
    }
}
// Total: O(n log n)
```

#### Derivation

For a fixed $i \geq 1$, the while loop runs $\lfloor \log_2 i \rfloor + 1$ times (see Worked Example 3). For $i = 0$ it runs 0 times. Summing over the outer loop:

$$
\begin{aligned}
\sum_{i=1}^{n-1} \left(\lfloor \log_2 i \rfloor + 1\right)
  &\leq \sum_{i=1}^{n-1} \log_2 i + n \\
  &= \log_2\big((n-1)!\big) + n \\
  &\leq n \log_2 n + n = O(n \log n)
\end{aligned}
$$

The step $\log_2((n-1)!) \leq n\log_2 n$ holds because $(n-1)!$ is a product of fewer than $n$ factors, each less than $n$. For the lower bound, look only at the top half $i \geq n/2$. Each of those roughly $n/2$ terms is at least $\log_2(n/2)$, so the total is at least $\frac{n}{2}\log_2\frac{n}{2} = \Omega(n \log n)$. The bound is therefore tight: $\Theta(n \log n)$.

### 5. Sequential Steps Add, Then Simplify

```python
for i in range(n):    # O(n)
    print(i)
for j in range(n):    # O(n)
    print(j * j)
# Total: O(n) + O(n) = O(2n) = O(n)
```
```julia
for i in 1:n          # O(n)
    println(i)
end
for j in 1:n          # O(n)
    println(j * j)
end
# Total: O(n) + O(n) = O(2n) = O(n)
```
```ts
for (let i = 0; i < n; i++) {   // O(n)
  console.log(i);
}
for (let j = 0; j < n; j++) {   // O(n)
  console.log(j * j);
}
// Total: O(n) + O(n) = O(2n) = O(n)
```
```rust
for i in 0..n {       // O(n)
    println!("{i}");
}
for j in 0..n {       // O(n)
    println!("{}", j * j);
}
// Total: O(n) + O(n) = O(2n) = O(n)
```

After adding, drop constants and lower-order terms as usual.

### 6. Conditionals: Respect Which Inputs Reach Each Branch

```python
if len(arr) < 100:
    bubble_sort(arr)    # O(n²)
else:
    merge_sort(arr)     # O(n log n)
# Worst-case growth: O(n log n)
```
```julia
if length(arr) < 100
    bubble_sort!(arr)   # O(n²)
else
    merge_sort(arr)     # O(n log n)
end
# Worst-case growth: O(n log n)
```
```ts
if (arr.length < 100) {
  bubbleSort(arr);      // O(n²)
} else {
  mergeSort(arr);       // O(n log n)
}
// Worst-case growth: O(n log n)
```
```rust
if arr.len() < 100 {
    bubble_sort(&mut arr);  // O(n²)
} else {
    merge_sort(&arr);       // O(n log n)
}
// Worst-case growth: O(n log n)
```

For a worst-case bound, consider the most expensive **reachable** branch at each input size. Here bubble sort runs only for $n < 100$: its quadratic work is bounded by a fixed cutoff. As $n$ grows, only the merge-sort branch is taken, so the overall worst-case growth is $\Theta(n \log n)$.

If either branch could be chosen for arbitrarily large $n$, a quadratic branch would instead dominate the worst case. Branch conditions matter; do not simply pick the largest annotation.

## Analysing Recursive Algorithms

Recursion requires more care. You write a **recurrence relation** and then solve it.

### Setting Up a Recurrence

For a recursive function, identify:
1. The cost of work done at the current level (non-recursive part)
2. How many recursive calls are made
3. What size each subproblem is

**Example — binary search:**

```python
def binary_search(arr, target, lo, hi):
    if lo > hi:
        return -1
    mid = (lo + hi) // 2
    if arr[mid] == target:
        return mid
    elif arr[mid] < target:
        return binary_search(arr, target, mid + 1, hi)
    else:
        return binary_search(arr, target, lo, mid - 1)
```
```julia
# Call with lo = 1, hi = length(arr) (Julia is 1-based).
function binary_search(arr, target, lo, hi)
    if lo > hi
        return nothing
    end
    mid = (lo + hi) ÷ 2
    if arr[mid] == target
        return mid
    elseif arr[mid] < target
        return binary_search(arr, target, mid + 1, hi)
    else
        return binary_search(arr, target, lo, mid - 1)
    end
end
```
```ts
function binarySearch(arr: number[], target: number, lo: number, hi: number): number {
  if (lo > hi) {
    return -1;
  }
  const mid = Math.floor((lo + hi) / 2);
  if (arr[mid] === target) {
    return mid;
  } else if (arr[mid] < target) {
    return binarySearch(arr, target, mid + 1, hi);
  } else {
    return binarySearch(arr, target, lo, mid - 1);
  }
}
```
```rust
// Searches arr[lo..hi] with hi exclusive (call with 0, arr.len()), so there
// is no `mid - 1` to underflow. Same recurrence: one call on half the range.
fn binary_search(arr: &[i32], target: i32, lo: usize, hi: usize) -> Option<usize> {
    if lo >= hi {
        return None;
    }
    let mid = lo + (hi - lo) / 2;
    if arr[mid] == target {
        Some(mid)
    } else if arr[mid] < target {
        binary_search(arr, target, mid + 1, hi)
    } else {
        binary_search(arr, target, lo, mid)
    }
}
```

One recursive call on a problem of size $n/2$, constant work at each level:

$$
T(n) = T\!\left(\frac{n}{2}\right) + O(1)
$$

Solving by repeated substitution. Write the constant work as $c$ and unroll:

$$
\begin{aligned}
T(n) &= T\!\left(\tfrac{n}{2}\right) + c \\
     &= T\!\left(\tfrac{n}{4}\right) + c + c \\
     &= T\!\left(\tfrac{n}{8}\right) + 3c \\
     &\;\;\vdots \\
     &= T\!\left(\tfrac{n}{2^k}\right) + kc
\end{aligned}
$$

The recursion bottoms out when the subproblem has size 1, which means $n / 2^k = 1$, or $k = \log_2 n$. Substituting:

$$
T(n) = T(1) + c\log_2 n = O(\log n)
$$

**Example — merge sort:**

```python
def merge_sort(arr):
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    left = merge_sort(arr[:mid])    # T(n/2)
    right = merge_sort(arr[mid:])   # T(n/2)
    return merge(left, right)       # O(n)
```
```julia
# merge_sorted, not merge: Base.merge already exists (for dictionaries)
function merge_sort(arr)
    if length(arr) <= 1
        return arr
    end
    mid = length(arr) ÷ 2
    left = merge_sort(arr[1:mid])       # T(n/2)
    right = merge_sort(arr[mid+1:end])  # T(n/2)
    return merge_sorted(left, right)    # O(n)
end
```
```ts
function mergeSort(arr: number[]): number[] {
  if (arr.length <= 1) {
    return arr;
  }
  const mid = Math.floor(arr.length / 2);
  const left = mergeSort(arr.slice(0, mid));  // T(n/2)
  const right = mergeSort(arr.slice(mid));    // T(n/2)
  return merge(left, right);                  // O(n)
}
```
```rust
fn merge_sort(arr: &[i32]) -> Vec<i32> {
    if arr.len() <= 1 {
        return arr.to_vec();
    }
    let mid = arr.len() / 2;
    let left = merge_sort(&arr[..mid]);   // T(n/2)
    let right = merge_sort(&arr[mid..]);  // T(n/2)
    merge(&left, &right)                  // O(n)
}
```

Two recursive calls on $n/2$, linear merge step:

$$
T(n) = 2T\!\left(\frac{n}{2}\right) + O(n)
$$

### The Master Theorem

The Master Theorem solves recurrences of the form:

$$
T(n) = aT\!\left(\frac{n}{b}\right) + f(n)
$$

where $a \geq 1$ is the number of subproblems, $b > 1$ is the shrink factor, and $f(n)$ is the non-recursive work. Assume a constant-size base case with $T(1) = \Theta(1)$ and a nonnegative work function. Floors and ceilings in balanced splits do not normally change the resulting asymptotic bound.

Define the **critical exponent** $c^* = \log_b a$.

<div class="note-table" role="region" aria-labelledby="the-master-theorem" tabindex="0">

| Case | Condition | Solution |
|------|-----------|----------|
| **Case 1** | $f(n) = O(n^{c^* - \varepsilon})$ for some $\varepsilon > 0$ | $T(n) = \Theta(n^{c^*})$ |
| **Case 2** | $f(n) = \Theta(n^{c^*} \log^k n)$ for $k \geq 0$ | $T(n) = \Theta(n^{c^*} \log^{k+1} n)$ |
| **Case 3** | $f(n) = \Omega(n^{c^* + \varepsilon})$ for some $\varepsilon > 0$, **and** $a f(n/b) \leq \rho f(n)$ for some $\rho < 1$ and sufficiently large $n$ | $T(n) = \Theta(f(n))$ |

</div>

**Intuition:** Compare the cost of the recursive work ($n^{c^*}$) to the cost of the non-recursive work ($f(n)$). Whichever dominates determines the total cost. If they're equal (Case 2), you pick up an extra $\log$ factor.

**Applying it to merge sort:** $a = 2$, $b = 2$, $f(n) = n$.

$$
c^* = \log_2 2 = 1 \quad \Rightarrow \quad n^{c^*} = n
$$

$f(n) = n = \Theta(n^1 \log^0 n)$ — this is Case 2 with $k = 0$.

$$
T(n) = \Theta(n \log n) \checkmark
$$

**More examples:**

<div class="note-table" role="region" aria-label="Master Theorem recurrence examples" tabindex="0">

| Recurrence | Case | Result |
|---|---|---|
| $T(n) = 2T(n/2) + n$ | 2 | $\Theta(n \log n)$ |
| $T(n) = 4T(n/2) + n$ | 1 | $\Theta(n^2)$ |
| $T(n) = T(n/2) + n$ | 3 | $\Theta(n)$ |
| $T(n) = 9T(n/3) + n^2$ | 2 | $\Theta(n^2 \log n)$ |
| $T(n) = 2T(n/2) + n^2$ | 3 | $\Theta(n^2)$ |

</div>

#### Derivation for each row

For each recurrence, identify $a$, $b$, and $f(n)$; compute $c^* = \log_b a$, then compare $f(n)$ with $n^{c^*}$:

1. **$T(n) = 2T(n/2) + n$**

   $a = 2$, $b = 2$, $f(n) = n$. So $c^* = \log_2 2 = 1$ and $n^{c^*} = n$.

   $f(n) = n = \Theta(n^1 \log^0 n)$ matches **Case 2** with $k = 0$. Thus $T(n) = \Theta(n \log n)$.

2. **$T(n) = 4T(n/2) + n$**

   $a = 4$, $b = 2$, $f(n) = n$. So $c^* = \log_2 4 = 2$ and $n^{c^*} = n^2$.

   $f(n) = n = O(n^{2 - \varepsilon})$ with $\varepsilon = 1$: recursive work dominates. **Case 1** gives $T(n) = \Theta(n^2)$.

3. **$T(n) = T(n/2) + n$**

   $a = 1$, $b = 2$, $f(n) = n$. So $c^* = \log_2 1 = 0$ and $n^{c^*} = 1$.

   $f(n) = n = \Omega(n^{0 + \varepsilon})$ with $\varepsilon = 1$. For **Case 3**, also check regularity ($a f(n/b) \leq k f(n)$ for some $k < 1$): $1 \cdot \frac{n}{2} = \frac{1}{2}n$ ✓. Thus $T(n) = \Theta(n)$.

   Sanity check: unrolling gives $n + \frac{n}{2} + \frac{n}{4} + \cdots \leq 2n$.

4. **$T(n) = 9T(n/3) + n^2$**

   $a = 9$, $b = 3$, $f(n) = n^2$. So $c^* = \log_3 9 = 2$ and $n^{c^*} = n^2$.

   $f(n) = n^2 = \Theta(n^2 \log^0 n)$ matches **Case 2** with $k = 0$. Thus $T(n) = \Theta(n^2 \log n)$.

5. **$T(n) = 2T(n/2) + n^2$**

   $a = 2$, $b = 2$, $f(n) = n^2$. So $c^* = \log_2 2 = 1$ and $n^{c^*} = n$.

   $f(n) = n^2 = \Omega(n^{1 + \varepsilon})$ with $\varepsilon = 1$. Regularity holds: $2 \cdot \left(\frac{n}{2}\right)^2 = \frac{1}{2}n^2$ ✓. **Case 3** gives $T(n) = \Theta(n^2)$.

#### Recursion-tree view: why Case 2 picks up a log

For merge sort, level $j$ of the tree has $2^j$ subproblems of size $n/2^j$. Each level therefore does $2^j \cdot \frac{n}{2^j} = n$ work. There are $\log_2 n + 1$ levels, so the total is $n(\log_2 n + 1) = \Theta(n \log n)$. In Case 1 the per-level cost grows geometrically toward the leaves, so the leaves dominate. In Case 3 it shrinks geometrically, so the root dominates.

> The Master Theorem does **not** apply when subproblems have unequal sizes (e.g., $T(n) = T(n/3) + T(2n/3) + n$) — use the recursion tree method instead.

### Tail Recursion

A tail-recursive function has no work left after its recursive call returns. A compiler or runtime can replace such calls with jumps, avoiding stack growth, but an accumulator alone does not guarantee this. For these Python, Julia, TypeScript-on-V8, and Rust examples, count $O(n)$ stack space unless you have verified tail-call optimisation in the actual runtime or build.

```python
# Not tail-recursive: must return to multiply after recursive call
def factorial(n):
    if n == 0: return 1
    return n * factorial(n - 1)   # multiplication happens *after*

# Tail-recursive (accumulator pattern)
def factorial_tail(n, acc=1):
    if n == 0: return acc
    return factorial_tail(n - 1, acc * n)   # no pending work
```

end

## Amortized Analysis

Amortized analysis bounds the total cost of a sequence and divides by the number of operations. It is not a probabilistic average over random inputs: the sequence can include expensive operations, and the total-cost bound still holds.

### Aggregate Method

Sum the total cost of $n$ operations, then divide by $n$.

**Dynamic-array model:** suppose capacity doubles when full. Starting at capacity 1, resizes copy $1, 2, 4, \ldots$ elements. Up to $n$ appends, this geometric sum is less than $2n$. Add the $n$ new-element writes: total work is $\Theta(n)$, or **amortized $\Theta(1)$ per append**.

CPython lists use a smaller over-allocation factor, not literal doubling. Their growth policy still gives amortized $O(1)$ append for ordinary list elements; doubling is the simplified model used for the proof.

### Accounting Method

Assign each operation a "charge". Cheap operations are overcharged; the surplus credit pays for expensive operations later.

**Stack with multi-pop:** Each element is pushed once (charge 2: 1 for the push, 1 saved as credit) and popped at most once (paid for by its credit). Any sequence of $n$ push/pop/multi-pop operations costs $O(n)$ total — amortized $O(1)$ each.

### Potential Method

Define a potential function $\Phi$ over the data structure's state. Amortized cost = actual cost + $\Delta\Phi$.

This is the most general method, used to analyse splay trees, Fibonacci heaps, and similar structures. Beyond typical interview scope but worth knowing exists.

#### Derivation

Let $n = \texttt{len(arr)}$. The outer loop runs $n$ times, and the inner loop always runs exactly 100 times. Total `print` calls:

$$
\sum_{i=0}^{n-1} 100 = 100n
$$

By the definition of Big O, $100n \leq c \cdot n$ with $c = 100$ for every $n \geq 1$, so $T(n) = O(n)$. The inner loop also always runs, so $100n \geq 1 \cdot n$ and the bound is tight: $\Theta(n)$.

</div>

<div class="example-derivation">

#### Derivation

Count how many times the inner body runs for each value of $i$:

| $i$ | 0 | 1 | 2 | $\cdots$ | $n-1$ |
|---|---|---|---|---|---|
| inner iterations | 0 | 1 | 2 | $\cdots$ | $n-1$ |

Let $S = 0 + 1 + \cdots + (n-1)$. Write the same sum backwards and add the two versions term by term:

$$
\begin{aligned}
S  &= 0 + 1 + \cdots + (n-1) \\
S  &= (n-1) + (n-2) + \cdots + 0 \\
2S &= \underbrace{(n-1) + (n-1) + \cdots + (n-1)}_{n \text{ terms}} = n(n-1)
\end{aligned}
$$

So $S = \frac{n(n-1)}{2} = \frac{1}{2}n^2 - \frac{1}{2}n$. For the upper bound, $S \leq \frac{1}{2}n^2$. For the lower bound, $S \geq \frac{1}{4}n^2$ whenever $n \geq 2$. Together these give $\Theta(n^2)$, which is half the work of the full $n \times n$ loop but the same growth rate.

</div>

</section>

</div>

<div class="example-derivation">

#### Derivation

<section class="calculation-step">

##### 1. Trace a concrete input

For $n = 16$, integer division reaches 1 after four halvings, then needs one final pass to reach 0:

| Iterations ($k$) | Calculation | Value of $i$ |
|---|---|---|
| 0 | $16 / 2^0$ | 16 |
| 1 | $16 / 2^1$ | 8 |
| 2 | $16 / 2^2$ | 4 |
| 3 | $16 / 2^3$ | 2 |
| 4 | $16 / 2^4$ | 1 |
| 5 | $\lfloor 16 / 2^5 \rfloor$ | 0 (stop) |

</section>

<section class="calculation-step">

##### 2. Count the passes

After $k$ passes, $i = \lfloor n/2^k \rfloor$. The loop stops when this is 0:

$$
\begin{aligned}
\left\lfloor \frac{n}{2^k} \right\rfloor = 0
&\iff \frac{n}{2^k} < 1 \\
&\iff k > \log_2 n
\end{aligned}
$$

The smallest integer satisfying this is $\lfloor \log_2 n \rfloor + 1$. For example, $20 \to 10 \to 5 \to 2 \to 1 \to 0$ also takes five passes: $\lfloor \log_2 20 \rfloor + 1 = 5$.

</section>

<section class="calculation-step">

##### 3. Convert the count to a growth rate

Each pass does constant work, so for a constant $c > 0$:

$$
T(n) = c\left(\lfloor \log_2 n \rfloor + 1\right) + O(1) = \Theta(\log n)
$$

A different fixed divisor changes only the constant: $\log_3 n = \log_2 n / \log_2 3$. The extra final pass and rounding do not change logarithmic growth.

</section>

</div>

<aside class="example-takeaway" aria-label="Halving intuition">

#### Why this stays fast

Doubling $n$ adds one iteration: the first halving brings $2n$ back to $n$.

| Input $n$ | Iterations |
|---|---|
| 1,000 | 10 |
| 1,000,000 | 20 |
| 1,000,000,000 | 30 |

**The binary view:** `i // 2` removes the last binary digit. For example:

$$
10100_2 \to 1010_2 \to 101_2
$$

Those values are 20, 10, and 5. The loop runs once per binary digit of $n$, which has $\lfloor \log_2 n \rfloor + 1$ digits.

</aside>

</section>

<div class="example-derivation">

#### Derivation

The three steps run one after another, so their costs add:

$$
T(n) = c_1 n + c_2 n\log_2 n + c_3 n
$$

For $n \geq 2$ we have $\log_2 n \geq 1$, so $n \leq n\log_2 n$. Replacing each linear term with $n \log_2 n$ gives an upper bound:

$$
T(n) \leq (c_1 + c_2 + c_3)\, n \log_2 n \quad \text{for all } n \geq 2
$$

This fits the Big O definition with $c = c_1 + c_2 + c_3$ and $n_0 = 2$, so $T(n) = O(n \log n)$. The ratio $\frac{n}{n \log n} = \frac{1}{\log n} \to 0$ shows that the linear passes are $o(n \log n)$: they become negligible as $n$ grows.

### Example 5 — Binary search + linear work

**Input:** a sorted array of $n$ values and a target. The function finds the leftmost occurrence by searching, then scanning left through duplicates.

```python
def example(arr, target):
    # Binary search: O(log n)
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target:
            # Then scan outward linearly: O(n)
            left = mid
            while left > 0 and arr[left - 1] == target:
                left -= 1
            return left
        elif arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```

  let lo = 0;
  let hi = arr.length - 1;

    const mid = Math.floor((lo + hi) / 2);
    if (arr[mid] === target) {
      // Then scan outward linearly: O(n)
      let left = mid;

        left -= 1;
      }

```rust
fn example(arr: &[i32], target: i32) -> Option<usize> {
    // Binary search: O(log n). hi is exclusive, so it never underflows.
    let (mut lo, mut hi) = (0, arr.len());
    while lo < hi {
        let mid = lo + (hi - lo) / 2;
        if arr[mid] == target {
            // Then scan outward linearly: O(n)
            let mut left = mid;
            while left > 0 && arr[left - 1] == target {
                left -= 1;
            }
            return Some(left);
        } else if arr[mid] < target {
            lo = mid + 1;
        } else {
            hi = mid;
        }
    }
    None
}
```

<div class="example-result">

**Time (worst case):** $\Theta(n)$. **Extra space:** $O(1)$. The duplicate scan can dominate the logarithmic search.

</div>

<div class="example-derivation">

#### Derivation

- **Search phase.** Each iteration of the outer `while` halves the interval `[lo, hi]`, just as in Example 3. It therefore runs at most $\lfloor \log_2 n \rfloor + 1$ times, which is $O(\log n)$.
- **Scan phase.** The scan runs at most once, because the function returns right after it. It moves `left` from `mid` down toward 0, so it does at most `mid` $\leq n - 1$ steps.
- **Total.** $T(n) \leq c_1 \log_2 n + c_2 n = O(n)$.
- **Worst case is tight.** Suppose every element equals `target`. The first probe hits `mid` $= \lfloor (n-1)/2 \rfloor$, and the scan then walks all the way to index 0. That is about $n/2$ steps, so the worst case is $\Theta(n)$.
- **Best case.** If the first probe finds the leftmost occurrence, the function returns after constant work: $\Theta(1)$. With no duplicates, the scan is constant, and the search still has $O(\log n)$ worst-case time.

Replacing the scan with a second binary search for the leftmost occurrence makes the whole function $O(\log n)$ in every case.

</div>

</section>

<section class="worked-example" aria-labelledby="example-6--recursive-tree-two-branches">

### Example 6 — Recursive tree (two branches)

**Input:** a nonnegative integer $n$. As throughout this note, treat arithmetic as constant-cost rather than analysing the bit length of Fibonacci values.

```python
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)
```
```julia
function fib(n)
    if n <= 1
        return n
    end
    return fib(n - 1) + fib(n - 2)
end
```
```ts
function fib(n: number): number {
  if (n <= 1) {
    return n;
  }
  return fib(n - 1) + fib(n - 2);
}
```
```rust
fn fib(n: u64) -> u64 {
    if n <= 1 {
        return n;
    }
    fib(n - 1) + fib(n - 2)
}
```

<div class="example-result">

**Time:** $\Theta(\phi^n)$, where $\phi = (1 + \sqrt 5)/2 \approx 1.618$. **Extra space:** $\Theta(n)$.

Each non-base call branches into sizes $n-1$ and $n-2$. The branches reach their base cases at different depths, so not every level doubles completely. $O(2^n)$ is a convenient loose upper bound; $\Theta(\phi^n)$ is the tight rate.

</div>

<div class="example-derivation">

#### Derivation

Let $C(n)$ be the number of calls. Then $C(0) = C(1) = 1$ and $C(n) = C(n-1) + C(n-2) + 1$.

##### 1. Bound the call count from above

Since $C(n-2) \leq C(n-1)$:

$$
C(n) \leq 2C(n-1) + 1
$$

Unrolling this gives $C(n) \leq 2^{n+1} - 1$. So $T(n) = O(2^n)$.

##### 2. Bound the call count from below

Since $C(n-1) \geq C(n-2)$:

$$
C(n) \geq 2C(n-2)
$$

Each application of this step subtracts 2 from $n$, so it can be applied $\lfloor n/2 \rfloor$ times before reaching a base case. That gives $C(n) \geq 2^{\lfloor n/2 \rfloor} = \Omega(\sqrt{2}^{\,n}) \approx \Omega(1.414^n)$. The call count is therefore exponential either way.

##### 3. Find the exact growth rate

Ignoring the $+1$ temporarily, guess a solution of the form $C(n) = x^n$:

$$
x^n = x^{n-1} + x^{n-2} \;\Rightarrow\; x^2 = x + 1 \;\Rightarrow\; x = \frac{1 \pm \sqrt{5}}{2}
$$

The larger root $\phi \approx 1.618$ dominates, which gives $\Theta(\phi^n)$. In fact $C(n) = 2F(n+1) - 1$, where $F$ is the Fibonacci sequence with $F(1) = F(2) = 1$. Check: $C(2) = 2F(3) - 1 = 2 \cdot 2 - 1 = 3$, which counts `fib(2)`, `fib(1)`, and `fib(0)` ✓.

##### 4. Count the stack frames

Only one root-to-leaf path is on the stack at a time. The longest path is $n \to n-1 \to \cdots \to 1$, which is $n$ frames, so space is $O(n)$.

</div>

</section>

<section class="worked-example" aria-labelledby="example-7--memoised-recursion">

### Example 7 — Memoised recursion

**Input:** a nonnegative integer $n$, starting with an empty cache. Repeated calls with a populated cache have a different cost.

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)
```
```julia
# A fresh memo per top-level call: Julia evaluates default arguments on
# every call. (The Memoize.jl package offers an @memoize macro.)
function fib(n, memo = Dict{Int, Int}())
    n <= 1 && return n
    haskey(memo, n) && return memo[n]
    memo[n] = fib(n - 1, memo) + fib(n - 2, memo)
    return memo[n]
end
```
```ts
function fib(n: number, memo = new Map<number, number>()): number {
  if (n <= 1) return n;
  const cached = memo.get(n);
  if (cached !== undefined) return cached;
  const result = fib(n - 1, memo) + fib(n - 2, memo);
  memo.set(n, result);
  return result;
}
```
```rust
use std::collections::HashMap;

// Call it as fib(n, &mut HashMap::new()).
fn fib(n: u64, memo: &mut HashMap<u64, u64>) -> u64 {
    if n <= 1 {
        return n;
    }
    if let Some(&cached) = memo.get(&n) {
        return cached;
    }
    let result = fib(n - 1, memo) + fib(n - 2, memo);
    memo.insert(n, result);
    result
}
```

<div class="example-result">

**Time:** $\Theta(n)$. **Extra space:** $\Theta(n)$.

Each non-base subproblem is computed once and cached. Base cases and cache hits take constant work.

</div>

<div class="example-derivation">

#### Derivation

- **Count the subproblems.** The only arguments that can ever appear are $0, 1, \ldots, n$, which is $n + 1$ distinct values.
- **Cost per subproblem.** A non-base cache miss does $O(1)$ work of its own plus two recursive calls. Cache hits and base-case calls cost $O(1)$.
- **Count all calls.** Each of the $n + 1$ first calls triggers at most 2 further calls, so there are at most $1 + 2(n+1)$ calls in total.
- **Time.** $O(1)$ per call times $O(n)$ calls gives $T(n) = O(n)$.
- **Space.** The cache holds at most $n + 1$ entries; these implementations differ in whether base cases are cached. The initial descent has $\Theta(n)$ live frames. Cache and stack are both linear, so peak extra space is $\Theta(n)$.

Compared with Example 6, caching takes the time from $\Theta(\phi^n)$ down to $\Theta(n)$ without changing the stack depth.

</div>

</section>

<section class="worked-example" aria-labelledby="example-8--nested-recursion">

### Example 8 — Nested recursion

**Input:** positive integers $n$ and $m$. Both are independent size parameters; zero-valued arguments are the recursion's base cases.

```python
def f(n, m):
    if n == 0 or m == 0:
        return 1
    return f(n - 1, m) + f(n, m - 1)
```
```julia
function f(n, m)
    if n == 0 || m == 0
        return 1
    end
    return f(n - 1, m) + f(n, m - 1)
end
```
```ts
function f(n: number, m: number): number {
  if (n === 0 || m === 0) {
    return 1;
  }
  return f(n - 1, m) + f(n, m - 1);
}
```
```rust
fn f(n: u64, m: u64) -> u64 {
    if n == 0 || m == 0 {
        return 1;
    }
    f(n - 1, m) + f(n, m - 1)
}
```

<div class="example-result">

**Time without memoisation:** $O\!\left(\binom{n+m}{n}\right)$. **Time and space with memoisation:** $O(n \cdot m)$.

This computes a value on a 2D grid of size $n \times m$. Without memoisation, the call count is exponential for a square grid. With memoisation, there are $n \times m$ unique subproblems.

</div>

<div class="example-derivation">

#### Derivation

##### 1. Identify what the function returns

The base cases return 1, and the recursion follows Pascal's rule:

$$
\begin{aligned}
\binom{n+m}{n}
  &= \binom{n+m-1}{n-1} \\
  &\quad + \binom{n+m-1}{n}
\end{aligned}
$$

So:

$$
f(n, m) = \binom{n+m}{n}
$$

This counts monotone lattice paths from $(0, 0)$ to $(n, m)$, using only right and up steps.

##### 2. Count calls without memoisation

Every leaf of the call tree returns exactly 1, and each internal call returns the sum of its two children. The number of leaves therefore equals the return value:

$$
L = \binom{n+m}{n}
$$

Every internal node has exactly two children. A tree with $L$ leaves has $2L - 1$ nodes, so the call count is:

$$
2\binom{n+m}{n} - 1 = \Theta\!\left(\binom{n+m}{n}\right)
$$

For a square grid ($n = m$), Stirling's approximation gives:

$$
\binom{2n}{n} \sim \frac{4^n}{\sqrt{\pi n}}
$$

That is exponential. For example, $f(20, 20) = \binom{40}{20} \approx 1.4 \times 10^{11}$ leaves.

##### 3. Count states with memoisation

- **States.** The possible arguments are pairs $(i, j)$ with $0 \leq i \leq n$ and $0 \leq j \leq m$, which is $(n+1)(m+1)$ states.
- **Work per state.** $O(1)$ plus two cache lookups.
- **Time.** $(n+1)(m+1) \cdot O(1) = O(nm)$.
- **Space.** Count the $O(nm)$ cache and $O(n+m)$ stack together: $O(nm+n+m)$. For positive $n,m$, $n+m \leq 2nm$, so the total is $O(nm)$ even when one dimension is small.

</div>

</section>

## Common Mistakes

1. **Treating $O(1)$ as "fast"** — it means *constant in the chosen input size*, not *small*. A fixed loop of ten million iterations is still $O(1)$ in $n$, but may be expensive.

2. **Missing hidden work** — `x in list` is $O(n)$ and `list.copy()` is $O(n)$. Repeatedly copying a growing string can be quadratic. Check library costs and what actually gets copied.

3. **Forgetting call stack space** — a recursive function with depth $d$ uses $O(d)$ stack space, regardless of what else it allocates. A depth-$n$ recursion on large $n$ can cause a stack overflow.

4. **Assuming hash operations are always $O(1)$** — average case yes, but worst case (all keys collide to the same bucket) is $O(n)$. Python's hash function is good, but adversarial inputs can degrade performance. Use `O(1)` average in analysis, but know the caveat.

5. **Applying rules across different variables** — $O(n + m)$ cannot be simplified to $O(n)$ unless you know $m = O(n)$. Graphs, matrices, and multi-input problems frequently have two independent size parameters.

6. **Ignoring the base case in recursion** — calls must terminate, and the recurrence must include the actual base-case cost. That cost need not be $O(1)$; assuming it is can invalidate the analysis.

7. **Over-applying the Master Theorem** — it only applies to recurrences of the form $T(n) = aT(n/b) + f(n)$ with balanced equal-size subproblems. Floors and ceilings are usually harmless, but unequal splits need a different analysis. It does not apply to $T(n) = T(n-1) + O(1)$ (use substitution) or $T(n) = T(n/3) + T(2n/3) + n$ (use recursion tree).

### Q1 — Upper bound or tight bound?

Can a worst-case running-time function be $O(n)$ without being $\Theta(n)$? Give an example.

<details class="review-answer">
<summary>Show answer</summary>

Yes. Binary search has worst-case time $\Theta(\log n)$, so $O(n)$ is a valid but loose upper bound. It is not $\Theta(n)$: the worst-case function grows more slowly than a linear lower bound. Keep the case fixed when comparing bounds.

</details>

</section>

<section class="review-question" aria-labelledby="q2--a-logarithmic-loop-inside-a-linear-loop">

### Q2 — A logarithmic loop inside a linear loop

What is the time complexity? Count the inner iterations for a given $i$.

```python
for i in range(n):
    j = 1
    while j <= i:
        j *= 2
```

```julia
for i in 0:(n - 1)
    j = 1
    while j <= i
        j *= 2
    end
end
```

```typescript
for (let i = 0; i < n; i++) {
  let j = 1;
  while (j <= i) {
    j *= 2;
  }
}
```

```rust
for i in 0..n {
    let mut j = 1;
    while j <= i {
        j *= 2;
    }
}
```

<details class="review-answer">
<summary>Show answer</summary>

For $i \geq 1$, the inner loop runs $\lfloor\log_2 i\rfloor + 1$ times. Every outer iteration costs at most $O(\log n)$, giving an $O(n\log n)$ upper bound. The last roughly $n/2$ iterations each cost $\Theta(\log n)$, giving a matching lower bound. Total time is $\Theta(n\log n)$.

</details>

</section>

### Q3 — Independent input sizes

An algorithm makes one pass over $m$ items, then one pass over $n$ items, with constant work per item. What is its complexity?

<details class="review-answer">
<summary>Show answer</summary>

$\Theta(m+n)$, equivalently $\Theta(\max(m,n))$. Keep both parameters unless the problem gives a relationship between them; $O(m)$ alone can miss the cost of the second input.

</details>

</section>

<section class="review-question" aria-labelledby="q4--constants-and-crossover-points">

### Q4 — Constants and crossover points

Suppose two implementations have modelled costs $n^2$ and $1000n\log_2 n$. Which is cheaper for a given $n$?

<details class="review-answer">
<summary>Show answer</summary>

Compare the actual expressions. The quadratic model is cheaper when $n < 1000\log_2 n$; the linearithmic model eventually wins as $n$ grows. Asymptotic order alone does not decide which implementation is faster at a small input size.

</details>

</section>

<section class="review-question" aria-labelledby="q5--growing-strings">

### Q5 — Growing strings

You concatenate $n$ one-character parts, and every concatenation copies the entire existing prefix. Why is this quadratic? What changes with a single join?

<details class="review-answer">
<summary>Show answer</summary>

The copied lengths are $1+2+\cdots+n = n(n+1)/2$, so total copying is $\Theta(n^2)$. A join copies the characters into one allocated result, giving $\Theta(n)$ work for these $n$ one-character parts. This question assumes prefix copying; do not infer that every runtime implements local string `+=` identically.

</details>

</section>

<section class="review-question" aria-labelledby="q6--work-versus-live-memory">

### Q6 — Work versus live memory

Why does naive recursive Fibonacci have exponential time but only linear stack space?

<details class="review-answer">
<summary>Show answer</summary>

Time counts every node visited in the recursion tree: $\Theta(\phi^n)$, or the looser upper bound $O(2^n)$. Space counts the deepest simultaneously live path, which is $\Theta(n)$ frames. Memoization reduces repeated work to $\Theta(n)$ time, but the cache and initial call-stack descent still need $\Theta(n)$ space.

</details>

</section>

<section class="review-question" aria-labelledby="q7--small-quadratic-subproblems">

### Q7 — Small quadratic subproblems

Why can insertion sort be useful inside a faster hybrid sorting algorithm?

<details class="review-answer">
<summary>Show answer</summary>

Small subarrays make the quadratic term small, while insertion sort has low overhead and good locality. A fixed-size base-case cutoff does not turn the whole sort quadratic. Many hybrids use this trade-off; the cutoff depends on the implementation.

</details>

</section>

<section class="review-question" aria-labelledby="q8--amortized-cost">

### Q8 — Amortized cost

In the doubling-capacity dynamic-array model, why do $n$ appends take linear total work despite occasional expensive resizes?

<details class="review-answer">
<summary>Show answer</summary>

The copied capacities form a geometric series $1+2+4+\cdots < 2n$. Add the $n$ ordinary writes: total work is $\Theta(n)$, so each append has amortized $\Theta(1)$ cost. A single resizing append can still cost $\Theta(n)$.

</details>

</section>

<section class="review-question" aria-labelledby="q9--a-shrinking-inner-loop">

### Q9 — A shrinking inner loop

A loop performs $n$ body operations on the first pass, $n-1$ on the next, and so on down to 1. What is the total?

<details class="review-answer">
<summary>Show answer</summary>

$\sum_{i=1}^{n} i = n(n+1)/2 = \Theta(n^2)$. The inner work shrinks, but its average is still proportional to $n$ across $n$ passes.

</details>

</section>

<section class="review-question" aria-labelledby="q10--construct-an-example">

### Q10 — Construct an example

Give a concrete algorithm with $\Theta(n)$ time and $O(\log n)$ extra space.

<details class="review-answer">
<summary>Show answer</summary>

Recursive depth-first traversal of an already-built **balanced binary tree** with $n$ nodes, doing constant work per visit. Every node is visited once, and the stack depth is the tree's $O(\log n)$ height. The bound assumes visits do not retain an output list; an unbalanced tree can instead need $O(n)$ stack space.

</details>
